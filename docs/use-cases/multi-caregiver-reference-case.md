# Synthetic multi-caregiver reference case

`scripts/build_case_bundle.py` generates one machine-readable case bundle for a single synthetic patient. It executes the existing delegation navigator, credential lifecycle, uploaded-care sharing policy, and clinical-holder fixture, then derives all display projections from their canonical identifiers.

The caregivers have separate bases: an invited family caregiver has a relationship claim and patient delegation grant, an agency CNA has a reviewed credential claim plus active assignment and service grant, and a community respite caregiver has a time-bounded assignment and service grant. The request selects a named authority path, but the caller cannot choose or weaken its requirements: `case-access.v1` fixes the required bases for each path and defaults to deny. The evaluator binds the exact request hash, patient, caregiver, application/audience, purpose, action, status, effective time, and reviewed item identifiers at each fresh request. The result includes historical permits followed by wrong-purpose, missing-claim, clinical-clarification, expiry, and fresh post-revocation denials at explicit evaluation times.

The bundle retains the uploaded-document review/correction record and approved-item lineage. A document item can reach an app only through the workforce/respite service-grant paths; a family scheduling delegation alone cannot disclose it. Application receipts contain the decision, purpose, policy identity, request hash, and only the approved minimum-data item. The item remains labeled as an uploaded-document statement with `clinically_authoritative: false`; receipts omit raw document packets, AI extraction text, unrelated claims, and clinical-holder payloads. The clinical-holder fixture is `executed_local` but explicitly has no live EHR, HIE, or network edge. This is synthetic local evidence, not a clinical chart, production authorization service, live registry, or live FHIR integration.
